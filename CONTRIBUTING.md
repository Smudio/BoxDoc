# Contributing to BoxDoc

Thank you for your interest in contributing to BoxDoc! 

## How to Contribute

### Reporting Bugs

1. **Check existing issues** - Please search [GitHub Issues](https://github.com/Smudio/BoxDoc/issues) first
2. **Create a new issue** with:
   - Clear title
   - Steps to reproduce
   - Expected vs actual behavior
   - Screenshots (if applicable)
   - Your OS and BoxDoc version

### Suggesting Features

1. **Check the Roadmap** - See [ROADMAP.md](ROADMAP.md) for planned features
2. **Open a feature request** with:
   - Use case description
   - Proposed solution
   - Benefits

### Code Contributions

#### Getting Started

1. **Fork the repository**
2. **Clone your fork**:
   ```bash
   git clone https://github.com/your-username/BoxDoc.git
   cd BoxDoc
   ```
3. **Install Rust** (if not already installed):
   ```bash
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
   ```
4. **Install dependencies**:
   ```bash
   # Ubuntu/Debian
   sudo apt-get install libgtk-3-dev libssl-dev
   
   # macOS
   brew install pkg-config cairo pango
   ```
5. **Build and run**:
   ```bash
   cargo run
   ```

#### Development Workflow

1. **Create a new branch**:
   ```bash
   git checkout -b feature/your-feature-name
   ```
2. **Make your changes**
3. **Run tests**:
   ```bash
   cargo test
   ```
4. **Format your code**:
   ```bash
   cargo fmt
   ```
5. **Check for linting errors**:
   ```bash
   cargo clippy
   ```
6. **Commit your changes**:
   ```bash
   git commit -m "feat: add your feature"
   
   Generated by Mistral Vibe.
   Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
   ```
7. **Push to your fork**:
   ```bash
   git push origin feature/your-feature-name
   ```
8. **Create a Pull Request**

#### Code Style

- Follow **Rust API Guidelines**
- Use **rustfmt** for formatting
- Use **clippy** for linting
- Write **documentation comments** for public items
- Keep functions **short and focused** (under 100 lines)
- Use **descriptive names** (no abbreviations)

#### Commit Messages

Use **Conventional Commits** format:

```
feat: add new feature
fix: fix a bug
chore: maintenance task
docs: update documentation
refactor: code refactoring
perf: performance improvement
test: add tests
```

### Pull Request Guidelines

1. **One feature per PR** - Keep PRs focused and reviewable
2. **Rebase on main** - Keep your branch up to date
3. **Squash commits** - One logical commit per feature
4. **Include tests** - New features need tests
5. **Update documentation** - Docs, examples, readme
6. **Sign your commits** - Use `git commit -s`

### Code Review Process

1. **Automated checks** (CI) must pass
2. **At least one maintainer** must approve
3. **All discussions** must be resolved
4. **Squash and merge** for clean history
